# 最优扭矩分配 (Control Allocation)

## 1. 一句话定义
> 最优扭矩分配是将VMC上层控制器输出的总力/力矩需求（Fx_des, Mz_des）分解为各轮扭矩指令（T_fl, T_fr, T_rl, T_rr）的数学过程。标准做法是将其建模为**含约束的二次规划 (QP)** 问题，在满足电机/轮胎/电池约束的前提下最小化分配误差。

## 2. 核心概念与公式

### 2.1 问题定式

```
已知:
  v_des = [Fx_des, Mz_des]ᵀ  (2维控制目标)
  u = [T_fl, T_fr, T_rl, T_rr]ᵀ  (4维执行器指令)

控制效能矩阵 B (2×4):
  [Fx_total]   [1/rw     1/rw     1/rw     1/rw    ] [T_fl]
  [        ] = [                                     ] [T_fr]
  [Mz_total]   [-tw_f/2rw tw_f/2rw -tw_r/2rw tw_r/2rw] [T_rl]
                                                       [T_rr]

问题: 4个未知数, 2个方程 → 无穷多解
→ 需要优化目标来选"最好的"一组解
```

### 2.2 标准QP形式

```
min   J = ||Wv·(B·u - v_des)||²      ← 控制误差
 u        + ||Wu·(u - u_prev)||²       ← 平滑性
          + ||Wε·u||²                  ← 能量最小化

s.t.  u_min ≤ u ≤ u_max               ← 执行器物理约束
      |u_i|/rw ≤ √((μ·Fz_i)² - Fy_est_i²)  ← 轮胎附着约束 (可选)
      Σ(P_loss_i) ≤ P_thermal_limit    ← 热约束 (可选)

其中:
  Wv = diag([w_Fx, w_Mz])  — Fx跟踪权重和Mz跟踪权重
    w_Mz >> w_Fx 通常 (横摆力矩跟踪精度比纵向力更重要)
  
  Wu: 平滑性权重 — 避免相邻时刻扭矩指令剧烈变化
  Wε: 能耗权重 — 最小化总功率消耗
```

### 2.3 转化为标准QP

```python
# 目标函数展开:
# J = (Bu - v)ᵀ·Wv·(Bu - v) + uᵀ·Wu·u
#   = uᵀ·(BᵀWvB + Wu)·u - 2·vᵀWvB·u + vᵀWv·v
#       \___________/          \_______/
#            H                     fᵀ
#
# 标准QP: min ½·uᵀ·H·u + fᵀ·u
#         s.t. A_ineq·u ≤ b_ineq
#              lb ≤ u ≤ ub

import numpy as np

def build_qp_matrices(B, v_des, u_prev, config):
    """构造扭矩分配QP的H, f矩阵"""
    
    # 权重
    w_Fx = 1.0       # 纵向力跟踪
    w_Mz = 10.0      # 横摆力矩跟踪 (更重要!)
    w_smooth = 0.1   # 平滑性
    w_energy = 0.01  # 能量效率
    
    n = 4  # 4个轮子
    
    # H = Bᵀ·Wv·B + Wu + Wε
    Wv = np.diag([w_Fx, w_Mz])
    H = B.T @ Wv @ B + w_smooth * np.eye(n) + w_energy * np.eye(n)
    
    # f = -Bᵀ·Wv·v_des - w_smooth·u_prev
    f = -B.T @ Wv @ v_des - w_smooth * u_prev
    
    return H, f
```

### 2.4 约束条件的层次

```
第一层: 硬件硬约束 (绝对不能违反)
  u_i ∈ [T_min_regen, T_max_motor]
  → 电机/电池的物理极限

第二层: 轮胎附着约束 (违反则失稳)
  |u_i|/rw ≤ √((μFz_i)² - Fy_i²)  
  → 如果某轮侧向力已很大, 其纵向力必须受限
  
  实现细节:
  → 需要每个轮子的 Fy_est (侧向力估计)
  → 需要每个轮子的 Fz_est (垂直载荷估计)
  → 需要 μ_est (路面附着系数估计)
  → 如果没有这些估计 → 用保守的上限替代

第三层: 软约束 (尽量满足)
  电池总功率 ≤ P_bat_limit
  → 如果实在需要超过 → 可短暂违反
  → 在QP中实现: 加松弛变量+大惩罚项
```

### 2.5 三电机构型的特殊QP

```
传统4WD (前后各1电机):
  前轴: 差速器均分 → T_fl = T_fr = T_front/2 (强约束!)
  后轴: 差速器均分 → T_rl = T_rr = T_rear/2 (强约束!)
  → QP降维: 4变量→2变量 (T_front, T_rear)

易三方 (前1, 后2独立):
  前轴: 差速器均分 → T_fl = T_fr = T_front/2 (约束)
  后轴: 独立控制 → T_rl, T_rr 完全自由
  → QP降维: 4变量→3变量 (T_front, T_rl, T_rr)
  → ★ 关键自由度在T_rl和T_rr的差动

从QP角度看:
  三电机的B矩阵列空间几乎满秩（除了前轴均分的退化）
  这意味着横摆力矩Mz基本可以通过后轴差动独立控制
  而不需要牺牲总驱动力Fx

约束差异:
  T_rl ∈ [T_min_regen, T_max_rear]  ← 可正可负
  T_rr ∈ [T_min_regen, T_max_rear]
  T_front ∈ [T_min_regen, T_max_front]  ← 通常与前轮转向耦合
```

### 2.6 求解器选择

| 求解器 | 类型 | 速度 | 嵌入友好 | 开源 | 适用场景 |
|--------|------|------|----------|------|----------|
| **qpOASES** | Active-set | ~100μs (小QP) | ★★★★ | LGPL | 嵌入式ECU |
| **OSQP** | ADMM | ~200μs | ★★★★ | Apache 2.0 | 嵌入式+仿真 |
| **CVXOPT** | Interior-point | ~1ms | ★★ | GPL | Python原型 |
| **ECOS** | Interior-point | ~1ms | ★★ | GPL | 参考验证 |
| **CVXPY** | 建模层 | N/A | ★ | Apache 2.0 | 快速原型 |
| **quadprog (MATLAB)** | Active-set | ~1ms | ★★ | 商业 | Simulink |

推荐路线: Python原型用OSQP → Simulink验证用qpOASES → 量产ECU移植自研精简QP

## 3. 我的理解

1. **扭矩分配是一个"过驱动系统"的控制分配问题**：
   - 输入维度(4个扭矩) > 输出维度(2个力/力矩)
   - 多出的自由度就是VMC可以做"优化"的空间
   - 三电机有3个自由度 → 比传统车(1~2个)有更大的优化空间

2. **QP的权重就是VMC的"调校哲学"**：
   - w_Mz/w_Fx大 → 稳定性优先 (操控取向)
   - w_Mz/w_Fx小 → 跟随性优先 (舒适取向)
   - w_smooth大 → 平顺但响应慢
   - w_energy大 → 节能但跟踪精度差
   - 这些权重暴露给标定工程师就是"驾驶模式"的数学基础

3. **流体力学类比**: 扭矩分配 ≈ 网格自适应的资源分配
   - 你把总计算资源分配到各网格点
   - 约束是每个网格的最小/最大分辨率
   - 目标是最小化全局误差
   - 数学结构完全一致

4. **为什么不是简单规则而是QP**：
   - 规则式: 已知工况下OK, 但复杂工况(对开路+弯道+加速)很难穷举
   - QP: 自动在所有约束下找到数学最优 → 鲁棒性更好
   - 但QP需要准确的Fy_est/Fz_est/μ_est → 状态估计不准, QP的"最优"也是垃圾

## 4. 与易三方平台的关联

- **后轴差动**是核心优化自由度，QP应优先利用这个自由度
- 前轴约束更紧(差速器均分) → QP求解时实质上是2.5维问题
- 单电机失效时, QP的约束边界会急剧变化（见三电机失效补偿知识条目）
- 坦克转向的扭矩分配逻辑与传统QP目标函数不同（目标从"横摆力矩跟踪"变成"最大化横摆角速度"）
