# 大脑-小脑（VMC）行业方案横向对比

## 1. 一句话定位
> 对比分析Tesla、比亚迪、华为、蔚来、博世、采埃孚的大脑-小脑/VMC方案，为易三方自研VMC提供技术路线参考。

## 2. 六大方案对比总表

| 维度 | Tesla | 比亚迪 璇玑 | 华为 途灵xMotion | 蔚来 ICC | 博世 VDC2.0 | 采埃孚 cubiX |
|------|-------|------------|-----------------|----------|------------|-------------|

## 3. 各方案深度分析

### 3.1 特斯拉: 极致垂直整合

```
架构特点:
  FSD Computer = 大脑 + 小脑 在同一块板子上!
  → 所有控制逻辑在一个SoC内完成
  → 信号路径: 传感器→FSD→执行器 (跳过了传统网关和域控)

与易三方的关系:
  ✗ 不可复制 (比亚迪不自己做AD芯片)
  ✓ 可借鉴: 将VMC算法跑在域控的高性能核上
  ✓ 可借鉴: Track Mode的扭矩分配逻辑
  ✓ 可借鉴: OTA驱动的VMC迭代模式
```

### 3.2 比亚迪 璇玑: 渐进式自研

```
架构推测 (基于公开信息):
  璇玑架构 = DiPilot(大脑) + 底盘域控(小脑)
  
  DiPilot:
    - 感知: 摄像头+毫米波+激光雷达(可选)
    - 芯片: NVIDIA Orin / 自研
    - 功能: ACC/LKA/NOA/AVP
    
  底盘域控 (推测为小脑所在):
    - iTAC (智能扭矩分配)
    - DiSus (云辇 主动悬架控制)
    - VMC (整车运动控制)
    - 可能位置: 底盘域控制器或VCU增强版

  易三方的VMC应该位于小脑中，需要确认:
    1. 小脑的确切硬件是谁做的？
    2. VMC算法目前是自研还是外采？
    3. 与DiPilot的接口协议是什么？
```

### 3.3 华为 途灵/xMotion: Tier 0.5 模式

```
架构:
  MDC (大脑, 可选) → 车控域控制器 (小脑, 含xMotion)
  
  xMotion = 华为的VMC品牌名
  → 纵向/侧向/垂向三向集成控制
  → 支持多执行器协调 (驱动+制动+转向+CDC+后轮转向)
  → 号称6自由度车辆运动控制

  DATS (Dynamic Adaptive Torque System):
  → 华为的扭矩矢量控制品牌
  → 实时路况感知 + AI扭矩分配

  关键信号: 华为以Tier 0.5模式深度参与主机厂研发
  → 比如与奇瑞、长安、北汽的深度合作
  → 提供从芯片到算法到云端的全栈方案
  → 主机厂可以选择采用部分或全部

  对比亚迪的启示:
  - 华为模式 = 高端但依赖外部
  - 易三方应该走介于"华为全栈"和"博世黑盒"之间的路线
  - 软件自研 + 芯片外购 + 执行器自研/外购混合
```

### 3.4 蔚来 ICC: 用户体验驱动

```
NIO Integrated Chassis Control (ICC):
  → 自研底盘域控制器
  → 集成: 驱动+制动+转向+空气悬架+CDC
  → 特色: 4D舒适控制 (融合地图预瞄+实时控制)

  分层:
    大脑 NAD → 输出轨迹
    小脑 ICC → 轨迹跟踪 + 舒适性优化
    执行层 → 各ECU

  特殊功能:
  - 湿地模式 (自动检测路面湿滑并调整控制策略)
  - ET9的线控转向 + 后轮转向 + 全主动悬架

  启示: 蔚来的VMC更多偏向"舒适性"维度，易三方可更偏向"操控性"
```

### 3.5 博世 VDC 2.0: 供应商标杆

```
Vehicle Dynamics Control 2.0:
  → ESP的升级版，加入驱动/转向/悬架的协调
  → VDIM (Vehicle Dynamics Integrated Management)
  → 黑盒交付: 主机厂只能调参数（标定），不能改算法

  优势: 成熟稳定，功能安全有保证
  劣势: 创新受限，差异化困难

  对易三方的影响:
  - 如果当前VMC完全依赖博世 → 需要策略性替换
  - 可以考虑"博世基础功能 + 自研高端功能"的混合路线
  - 三电机的非标扭矩分配算法博世肯定没有 → 这是自研的切入点
```

### 3.6 采埃孚 cubiX: 白盒/灰盒方案

```
cubiX = 采埃孚的底盘域控制软件平台
  → 可以跑在第三方硬件上
  → 白盒/灰盒交付 (主机厂可以看到部分源码)
  → 支持: 转向+制动+悬架+动力总成的协调

  对比博世:
  - 灵活性更高 (可定制)
  - 但生态不如博世成熟
  - 更像是一个"半成品"，主机厂需要自己集成
```

## 4. 关键差异维度深度对比

### 4.1 大脑-小脑耦合度

```
紧耦合 (Tesla、华为):
  大脑和小脑在同一平台 → 延迟低, 但升级耦合
  
松耦合 (蔚来、博世):
  大脑和小脑独立 → 可独立迭代, 但有通信开销
  
易三方建议: 松耦合方案
  → 比亚迪的DiPilot迭代周期 ≠ VMC迭代周期
  → 松耦合意味着VMC可以独立进化
  → 接口标准化是关键
```

### 4.2 VMC自研程度光谱

```
黑盒(供应商控制)  灰盒(联合开发)   白盒(自研为主)   全栈自研
  ←────────────────────────────────────────────────→
  博世VDC2.0    采埃孚cubiX    华为xMotion    Tesla
                              蔚来ICC        比亚迪(目标)
                              
易三方目标位置: ★白盒/自研为主
  → 轮胎模型: 自研 (核心资产)
  → 状态估计: 自研 (差异化来源)
  → 扭矩分配: 自研 (三电机特化)
  → 稳定性控制: 可在博世基础上优化
  → 执行器接口: 标准化
```

### 4.3 各方案的技术亮点总结

| 亮点 | 来源 | 可借鉴性 |
|------|------|----------|
| 全在FSD芯片内部完成控制 | Tesla | 低 (无自研芯片) |
| Track Mode用户可调VMC | Tesla | ★★★ 高端平台可做 |
| 云辇+VMC垂向联动 | 比亚迪 | ★★★★★ 已经在做 |
| iTAC智能扭矩分配 | 比亚迪 | ★★★★★ 三电机可做更好 |
| xMotion 6-DOF控制 | 华为 | ★★★★ 参考架构 |
| DATS路况自适应 | 华为 | ★★★★ 可自研类似功能 |
| 4D舒适控制(地图预瞄) | 蔚来 | ★★★ 锦上添花 |
| ICC域控制平台 | 蔚来 | ★★★★ 参考自研域控思路 |

## 5. 我的理解与判断

1. **易三方自研VMC的差异化空间在"三电机"**：
   - 没有任何供应商有三电机的标准VMC方案
   - 后轴双电机+前轴单电机的构型是独特的
   - 这就是自研的切入点——供应商做不了的、竞争对手短期追不上的

2. **应该"借"哪些、不应该"造"哪些**：
   - 应该自研: 三电机扭矩分配、状态估计、横摆力矩控制策略
   - 可以外采: 基础ESP功能、执行器底层控制、功能安全框架
   - 待定: MPC求解器（是用开源还是自研?）

3. **当前最关键的3个问题需要确认**：
   - Q1: 易三方当前的EEA阶段？域集中还是已有中央计算？
   - Q2: 当前VMC软件是谁在提供？（博世? 比亚迪自研? 联合开发?）
   - Q3: DiPilot→VMC的接口协议是什么？（轨迹? 加速度? 速度+横摆?）
