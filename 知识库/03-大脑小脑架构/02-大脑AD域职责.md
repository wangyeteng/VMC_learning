# 大脑（AD域）职责与大脑-小脑接口

## 1. 一句话定义
> "大脑"是整车智能驾驶域控制器及其软件栈的统称，负责**环境感知、行为决策、轨迹规划**——即回答"车在哪里、周围有什么、应该怎么走"。它不与执行器直接交互，而是将**运动意图**以标准化接口发给"小脑"(VMC)去执行。

## 2. 核心概念与公式

### 2.1 大脑的功能分层

```
┌─────────────────────────────────────────┐
│  感知层 (Perception)                     │
│  摄像头+毫米波+激光雷达+超声波+HD地图     │
│  → 检测: 车道线、车辆、行人、标志、红绿灯  │
│  → 输出: 目标列表 + 语义地图             │
├─────────────────────────────────────────┤
│  预测层 (Prediction)                     │
│  → 预测周围目标的未来轨迹 (3~8秒)         │
│  → 行为意图推测 (变道/转弯/停车)          │
├─────────────────────────────────────────┤
│  决策层 (Decision / Behavioral Planning) │
│  → 粗粒度行为: 跟车/变道/转弯/停车/绕行   │
│  → 参考路径选择                          │
├─────────────────────────────────────────┤
│  规划层 (Motion Planning)                │
│  → 细粒度轨迹: 未来N秒的(X,Y,ψ,速度)序列  │
│  → 碰撞检查 + 舒适性优化                 │
│  → 输出: 轨迹 → 发给VMC                  │
└─────────────────────────────────────────┘
```

### 2.2 大脑→小脑的四种接口模式

```
模式A: 轨迹接口 (Trajectory Interface) — 最"厚"的接口
  大脑输出: {X(t), Y(t), ψ(t), V(t)} 未来N秒
  小脑任务: 整车层面的轨迹跟踪控制
  适用: L3+ ADS, 中央计算架构
  代表: 特斯拉FSD, 华为ADS 3.0

模式B: 加速度+曲率接口 (Acceleration Interface)
  大脑输出: {ax_target, ay_target, κ_desired}
  小脑任务: 力和力矩分配
  适用: L2+ 辅助驾驶
  代表: 博世VDC2.0

模式C: 速度+横摆角速度接口 (Velocity+Yaw Interface)
  大脑输出: {Vx_target, r_target}
  小脑任务: 纵向控制+横摆控制+稳定性
  适用: ACC+LKA, 传统ADAS
  代表: 大多数L2方案

模式D: 直接执行器接口 (Direct Actuator Interface)
  大脑输出: {扭矩_前/后, 制动_各轮, 转角}
  小脑任务: 稳定性监控与兜底
  适用: 不需要（这是反模式，大脑不该直接控执行器）
```

### 2.3 大脑-小脑接口设计的关键权衡

```
                    大脑负责越多                   小脑负责越多
                    ←──────────────────────────→

 大脑算力需求:      高 ←──────────────────────→ 低
 小脑算力需求:      低 ←──────────────────────→ 高
 接口数据量:        大 ←──────────────────────→ 小
 耦合度:            紧 ←──────────────────────→ 松
 迭代独立性:        差 ←──────────────────────→ 好
 差异化空间:      大脑 ←──────────────────────→ 小脑
 (体验差异在哪层体现)

推荐: 模式A (轨迹接口) — 现代EEA下的最佳平衡点
```

### 2.4 大脑对小脑的反馈需求

```
小脑必须实时反馈给大脑:
  1. 当前车辆状态: Vx, Vy, r, β, ax, ay
  2. 执行能力边界: 当前轮胎附着状态, 可用横摆力矩余量
  3. 稳定性警示: β是否接近临界值, 是否有失稳风险
  4. 控制模式: 当前VMC处于什么模式(正常/运动/安全兜底)

目的: 大脑根据小脑反馈实时调整规划 ——
      如果小脑反馈"当前路面很滑, 横摆能力仅30%",
      大脑应该降低规划速度、增加转弯半径
```

## 3. 我的理解

1. **大脑和小脑的分工本质是"规划"与"执行"的分离**：
   - 大脑回答"往哪走"——与车辆动力学无关
   - 小脑回答"怎么走"——深刻依赖车辆动力学
   - 这种分离使得大脑可以跨车型复用，小脑需要为每个车型定制

2. **接口设计是自研VMC最关键的战略决策**：
   - 如果接口太"薄"（如模式D），VMC沦为执行器的安全监控，创新空间小
   - 如果接口太"厚"（如模式A），VMC需要自己做轨迹跟踪，技术挑战大但创新空间也大
   - **易三方应该选择模式A或B**，才能在高端平台上做出差异化

3. **"反馈"部分经常被忽视**：
   - 大脑不能只发指令不管反馈——就像你不能闭着眼走路
   - 好的小脑不仅要执行，还要告诉大脑"我现在的能力边界在哪"
   - 这需要VMC有准确的轮胎附着系数和稳定裕度估计能力

## 4. 与易三方平台的关联

- 易三方作为高端平台，应支持**模式A（轨迹接口）**，为未来L3+升级预留空间
- 三电机的冗余特性意味着小脑有更大的能力边界，大脑可以规划更大胆的轨迹
- 如果比亚迪的DiPilot（大脑）输出轨迹接口，VMC需要做**轨迹→力→扭矩**的完整解算链
- 这要求VMC团队的算法能力覆盖MPC、QP、状态估计等全部环节
