# 整车电子电气架构 (EEA) 演进

## 1. 一句话定义
> EEA (Electrical/Electronic Architecture) 是整车的"神经系统"——定义了控制器如何物理分布、如何通信、如何供电、如何协同工作。EEA的演进（分布式→域集中→中央计算）是VMC从"功能孤岛"走向"大脑-小脑协同"的底层使能因素。

## 2. 核心概念与公式

### 2.1 EEA三代演进

```

│   └──┬──┴──┬──┘         │      │    │ (大脑+小脑)  │      │      │    │ (大脑+小脑)  │      │
```

### 2.2 各代EEA对VMC的影响

| 特征 | 分布式 | 域集中 | 中央+区域 |
|------|--------|--------|-----------|
| VMC实现位置 | 各ECU独立逻辑 | 底盘域控制器 | 中央计算或底盘域 |
| 信号延迟 | 高(CAN总线串行) | 中(域内高速总线) | 低(以太网骨干) |
| 功能集成度 | 低(ESP/TCS/ABS独立) | 中(部分功能协调) | 高(全功能融合) |
| 软件升级 | 困难(各ECU独立刷写) | 部分可行 | 全域OTA |
| VMC创新空间 | 小(供应商锁定) | 中(可定制参数) | 大(全栈自研) |
| 大脑-小脑交互 | 不存在 | 通过网关 | 直接通信 |

### 2.3 关键通信协议

```
低速 (≤1Mbps):
  LIN: 19.2kbps — 车窗/座椅等
  CAN: 500kbps~1Mbps — 传统控制信号

中速 (1~10Mbps):
  CAN-FD: 2~5Mbps — 升级版CAN, 仍在广泛使用
  FlexRay: 10Mbps — BMW等曾使用, 正被替代

高速 (100Mbps~1Gbps+):
  Automotive Ethernet (100BASE-T1 / 1000BASE-T1)
    ├── SOME/IP: 服务导向通信 (上层协议)
    ├── DDS: 数据分发服务 (ROS2, Aptiv等采用)
    └── TSN: 时间敏感网络 (确定性延迟保证, 802.1Q)

VMC的实时性需求:
  稳定性控制: <10ms循环, <5ms延迟
  扭矩分配:   <5ms循环, <1ms延迟
  状态估计:   <10ms循环
  通信确定性: 硬实时 (不能丢帧/延迟)
```

## 3. 我的理解

1. **EEA决定了VMC的能力天花板**：
   - 分布式架构下，你无法实现全局最优的VMC——因为各ECU各自为政
   - 中央计算架构下，VMC可以从全局视角优化所有执行器
   - "自研VMC"的前提是"你有能力修改VMC的软件架构"——这要求EEA足够集中

2. **通信协议的选择很关键**：
   - CAN的1Mbps对于复杂VMC不够用（数据量太大）
   - SOME/IP适合SOA架构但实时性不如DDS
   - TSN是未来趋势但生态还不成熟
   - 现阶段折中方案：关键控制走CAN-FD（确定性强），大数据走以太网

3. **特斯拉的启示**：
   - Model 3的EEA只有3个域控制器（左、右、中央）→ 48个ECU→3个
   - 这是VMC创新的物理基础：所有底盘信号都在一个控制器里
   - 所以特斯拉的Track Mode（赛道模式）可以做到极致的扭矩分配

4. **比亚迪的EEA路径**：
   - e平台3.0：从分布式到域集中的关键一步
   - 璇玑架构：进一步向中央计算靠拢
   - 易三方/仰望这样的高端平台需要最灵活的EEA来释放VMC的潜力

## 4. 与易三方平台的关联

- 需要确认易三方的EEA处于哪个阶段（域集中？还是已有中央计算？）
- 三电机的闭环控制需要在哪个控制器中完成？（MCU? 底盘域控? 中央计算?）
- 如果EEA不够集中，分布式VMC算法的划分是一个关键设计决策
- 自研VMC的软件部署位置需要考虑功能安全等级（ASIL C/D）
