# 小脑（底盘域/VMC）职责与设计原则

## 1. 一句话定义
> 小脑（Cerebellum）在智能汽车架构中对应**底盘域控制器中的VMC软件**。它的核心职责是：接收大脑的运动意图（轨迹/加速度/横摆请求），在保证车辆稳定性和安全性的前提下，通过协调驱动、制动、转向、悬架等多执行器，精确地实现期望的车辆运动。

## 2. 核心概念与公式

### 2.1 小脑的完整职责清单

```
┌─────────────────────────────────────────────────────────┐
│                    小脑 (VMC) 职责                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 运动意图解译 (Intent Interpretation)                │
│     输入: 轨迹/加速度/横摆角速度 等不同形式              │
│     输出: 统一的车辆层面控制目标 (Fx_des, Mz_des)        │
│     ★ 核心: 不管大脑给什么形式的指令，都要能解译          │
│                                                         │
│  2. 参考模型生成 (Reference Generation)                  │
│     "在这个车速和方向盘转角下，理想的车应该怎么动？"      │
│     输出: r_ref, β_ref                                  │
│     约束: 轮胎物理极限                                   │
│                                                         │
│  3. 车辆状态观测 (State Observation)                     │
│     "车现在到底是什么状态？"                             │
│     核心输出: β (质心侧偏角), 轮胎力, 附着系数μ          │
│     方法: KF/EKF/UKF + 多传感器融合                     │
│     ★ 这是小脑最独特也最难的能力                         │
│                                                         │
│  4. 稳定性监控与干预 (Stability Supervision)             │
│     "车快失控了吗？需要我介入吗？"                       │
│     监控: β-β̇相平面位置, 各轮附着利用率η                 │
│     干预: 从"温和纠正"到"全力救车"的分级策略             │
│     ★ 这是小脑最核心的安全兜底职责                       │
│                                                         │
│  5. 执行器协调 (Actuator Coordination)                   │
│     "如何在驱动/制动/转向/悬架之间分配控制任务？"        │
│     原则: 在满足总目标的前提下最小化能量、最大化安全      │
│     方法: Control Allocation (QP/规则/伪逆)              │
│                                                         │
│  6. 能力边界反馈 (Capability Feedback)                   │
│     "告诉大脑我现在的能力边界"                           │
│     输出: 可用横摆力矩余量, 路面μ, 稳定裕度               │
│     ★ 没有这个反馈, 大脑的规划就是"盲规划"               │
│                                                         │
│  7. 故障检测与降级 (Fault Detection & Degradation)       │
│     "某个执行器坏了怎么办？"                             │
│     策略: 检测→隔离→降级→通知驾驶员/大脑                 │
│                                                         │
│  8. 驾驶模式管理 (Drive Mode Management)                 │
│     ECO/Normal/Sport/Track → 对应不同的控制参数集         │
│     ★ 驾驶模式 = QP权重的切换 + 参考模型的调校            │
└─────────────────────────────────────────────────────────┘
```

### 2.2 小脑设计的核心原则

```
原则1: 安全优先 (Safety First)
  稳定性 > 驾驶员意图 > 舒适性 > 能耗
  → VMC永远以"不翻车、不失控"为第一优先级
  → 即使这意味着"违抗"驾驶员/大脑的指令

原则2: 最小干预 (Minimal Intervention)
  → 正常行驶时: VMC几乎"隐身" (驾驶员感觉不到它的存在)
  → 接近极限时: VMC温和介入 (驾驶员察觉到"车在帮我")
  → 极度危险时: VMC全力接管 (保命优先)

原则3: 确定性实时 (Deterministic Real-time)
  控制周期: 5-10ms (100-200Hz)
  延迟要求: <1ms (从传感器读到执行器指令发出)
  → 错过一个控制周期可能意味着失稳

原则4: 可标定性 (Calibratability)
  → 控制参数必须能被标定工程师理解和调节
  → "驾驶模式"的本质: 不同参数集的命名集合
  → QP权重、SMC增益、MPC时域——这些都是标定对象

原则5: 功能安全 (Functional Safety)
  → VMC通常被分配 ASIL C 或 D (最高安全等级)
  → 需要硬件冗余、软件分区、故障检测全覆盖
  → 这是VMC量产的最大工程挑战(甚至大于算法本身)
```

### 2.3 小脑在大脑失效时的兜底角色

```
大脑失效模式与VMC的应对:

情况1: 大脑完全失效 (AD域控制器宕机)
  VMC行为: 立刻切换到"驾驶员直连"模式
  → 方向盘转角直接映射到参考r_ref
  → 加速踏板直接映射到Fx_des
  → VMC的核心稳定功能仍然100%生效
  → 驾驶员可以安全地将车驶到路边

情况2: 大脑给出的轨迹不合理 (如要求0.5秒内90°转向)
  VMC行为: 根据物理约束限幅
  → |r_ref| ≤ μg/Vx (物理法则不可违背)
  → 同时向大脑反馈 "执行能力不足"

情况3: 大脑与VMC之间的通信中断
  VMC行为: 保持上一时刻的合理指令, 同时降速
  → 如果连续N个周期没有收到大脑指令 → 触发安全停车
```

```
传统架构 (分布式):                  新架构 (域集中):
─────────────────                  ──────────────

EPS有自己的ECU ─┤                  │  │   VMC       │ │ ← 统一协调
CDC有自己的ECU ─┘                  │  │  (策略层)   │ │
                                   │  ├─────────────┤ │
冲突! 谁说了算?                     │  │ ESP/ABS/TCS │ │ ← 基础功能

```

## 3. 我的理解

1. **小脑不是"ESP的升级版"**——它是架构层面的变革。ESP是一个具体的功能（制动干预来稳定车辆），而VMC是一个**平台**——ESP可以运行在VMC平台之上作为其中一个执行策略。

2. **小脑最大的技术壁垒不是算法，而是标定数据**：
   - 轮胎模型参数需要大量实车测试（每个车型、每种轮胎组合都要标定）
   - 车辆惯量、质心位置需要精确测量
   - 这个"数据壁垒"是自研VMC的护城河

3. **大脑-小脑接口是战略决策点**：
   - 位置A（紧耦合）：大脑小脑在同一个SoC → Tesla路线
   - 位置B（松耦合）：大脑和小脑在不同控制器 → 大多数主机厂路线
   - 易三方建议B：松耦合更灵活，VMC可以独立迭代

## 4. 与易三方平台的关联

- 三电机意味着小脑的执行器协调能力需要更强（2个独立后轴电机带来的新自由度）
- VMC需要感知三电机的健康状态（单电机温度、功率限制等）并纳入约束
- 易三方的"特殊功能"（坦克转向等）是传统ESP/VMC做不到的 → 自研VMC的差异化价值
